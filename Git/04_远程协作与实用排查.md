# Git 远程协作与实用排查

返回 [Git 学习索引](00_Git学习索引.md)。远程仓库常被命名为 `origin`，但它只是一个普通的远程名；可用 `git remote -v` 查看实际地址。

## 同步远程的四个动作

| 命令 | 作用 | 是否改变当前工作区 |
| --- | --- | --- |
| `git fetch origin` | 下载远程提交和引用 | 否 |
| `git merge origin/main` | 把远程主线合并到当前分支 | 可能 |
| `git pull` | `fetch` 后再整合（默认通常是 merge） | 可能 |
| `git push origin <分支>` | 上传本地提交 | 否 |

建议先 `fetch` 再决定如何整合，这样可以用 `git log HEAD..origin/main --oneline` 预览远程多出来的提交。

```bash
# 查看远程及其地址
git remote -v

# 下载远程信息，但不改工作区
git fetch origin

# 只允许快进；若本地有分叉则停止，让你自行决定如何处理
git switch main
git pull --ff-only
```

## 推送新分支与上游关系

```bash
# 第一次推送；-u 让后续可以直接使用 git push / git pull
git push -u origin feat/export-report

# 查看本地分支跟踪的远程分支
git branch -vv
```

分支提交到远程后，通常创建 Pull Request / Merge Request，由代码审查、测试和平台的合并策略来保护主分支。

## 用 rebase 方式拉取更新

当团队约定功能分支历史保持线性时：

```bash
git pull --rebase origin main
```

这相当于先下载 `origin/main`，再将当前未推送的提交重新放到它之后。若本地已经推送过被 rebase 的提交，更新远程时使用更安全的：

```bash
git push --force-with-lease
```

`--force-with-lease` 会在远程分支出现你未见过的新提交时拒绝推送；它仍会改写远程历史，只应用于你独占的功能分支，切勿用于共享主分支。

## 标签：为发布版本做标记

```bash
# 创建带说明的标签
git tag -a v1.2.0 -m "Release v1.2.0"

# 推送单个标签或全部标签
git push origin v1.2.0
git push origin --tags

# 查看标签及其说明
git tag -n
```

标签应指向已经审核、可复现的提交。若团队有发布流程，请优先使用团队规定的版本号与发布工具。

## 常见场景速查

| 现象 | 先做什么 | 常用命令 |
| --- | --- | --- |
| `push` 被拒绝，提示远程领先 | 先获取远程变更并整合 | `git pull --ff-only` 或 `git fetch` 后自行 merge/rebase |
| 不小心在错误分支修改了文件 | 不要急着提交；先保存现场 | `git stash push -u`，切到正确分支后恢复 |
| 忘记当前改了什么 | 查看状态和差异 | `git status -sb`、`git diff` |
| 想看某行是谁改的 | 查看逐行历史 | `git blame <文件>` |
| 需要定位引入问题的提交 | 二分查找 | `git bisect start` |

`git blame` 的目的在于追溯上下文和理解决策，不应用于指责同事。

## 检查清单

在提交或推送前，依次确认：

```bash
git status -sb
git diff
git diff --staged
git log --oneline -5
```

- 当前分支是否正确？
- 暂存的文件是否刚好是这次任务需要的？
- 是否误把密钥、日志或构建产物放进提交？
- 是否已执行必要的测试、格式化或检查？
